🌿 ForêtMap

L’interface utilisateur est désormais livrée par le build Vite (dossier dist/).

Si le serveur tourne en production (NODE_ENV=production) et que vous voyez cette page, dist/ manquait au démarrage de Node : le serveur ne choisit qu’au démarrage de servir le build. dist/ n’est plus dans le dépôt : le cron de déploiement le pose depuis la branche dist-artifact/main, puis redémarre l’application.

Si cette page reste affichée : lire logs/foretmap-auto-deploy.log, puis suivre la section « Dépannage » de docs/DEPLOY_DIST_ARTIFACT.md (sans node : git archive de l’artefact dans dist/), et redémarrer l’application. Ne pas utiliser « Update from Remote » de cPanel, qui ne pose pas le build.

En développement : lancez le backend (ex. npm run dev sur le port 3000) et le client Vite (npx vite ou npm run dev:client) — voir docs/LOCAL_DEV.md dans le dépôt.

Après déploiement en production, exécutez npm run deploy:check:prod pour valider rapidement l’état de l’application et de la base.

Les assets publics (sw.js, images) restent dans public/ et sont copiés dans dist/ au build.
