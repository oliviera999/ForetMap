### Ajouté — Séances pédagogiques : étape « Tutoriel » (`open_tutorial`)

- **Nouvelle action d'étape `open_tutorial`** : une séance libre peut ouvrir un tutoriel
  par-dessus l'onglet Séances. L'aperçu réutilise la fenêtre des tutoriels (accusé de lecture
  compris pour un compte connecté) ; une fois fermé, le bouton « Tutoriel » du bandeau le
  rouvre, et la consigne de l'étape reste lisible dans l'onglet. Un tutoriel désactivé depuis
  la publication ne bloque pas l'élève : il est prévenu et poursuit la séance.
- **Validation serveur** : à chaque écriture des étapes (`POST` et `PUT /api/pedago-sessions`,
  brouillon compris), le tutoriel visé doit exister et être actif, sinon 400 avec le numéro de
  l'étape. `tutorialSlug` est accepté à l'écriture et résolu en `tutorialId`, seule forme
  enregistrée. Le contrôle de publication des séances libres couvre aussi les tutoriels.
- **Éditeur d'étape** : entrée « Tutoriel » dans « Outil ouvert », avec la liste des tutoriels
  actifs ; un tutoriel devenu indisponible reste affiché comme tel.
- **Connecteur** : le schéma de `foretmap_pedago_sessions` décrit la forme d'une étape, les
  actions disponibles et les champs de chaque `payload`.

## Pour SI

**Aucune ligne n'est demandée dans le shell.** L'état du tutoriel est porté par
`usePedagoSession` (`sessionTutorial`, `closeSessionTutorial`, `markSessionTutorialRead`), que
le shell transmet déjà tel quel à `PedagoSessionProvider` ; `PedagoSessionBanner` le lit dans
le contexte et rend `TutorialPreviewModal` (importé, non modifié).

Facultatif, à l'appréciation de SI :

1. `tests-ui/AppShellPedagoSessions.test.jsx` (fichier de SI) : un cas « étape tutoriel » de
   bout en bout dans le shell monté. Le comportement est couvert hors shell par
   `tests-ui/hooks/usePedagoSession.test.jsx` et
   `tests-ui/components/pedago/SessionsOpenTutorial.test.jsx`.
2. Déconnexion forcée depuis l'accusé de lecture : `TutorialPreviewModal` accepte
   `readAcknowledge.onForceLogout`, que seul le shell possède (`forceLogout`). Sans lui, un
   compte supprimé pendant la lecture n'est pas déconnecté depuis cet aperçu (il le sera à
   l'appel suivant). Pour l'ajouter : passer `forceLogout` dans `navigation` de
   `usePedagoSession` (`src/hooks/useAppPedago.js`), une ligne, puis le relayer au bandeau.
3. Onglet Tutoriels masqué : `routes/tutorials.js` n'a pas de garde de module, l'étape ouvre
   donc le tutoriel même quand l'onglet n'est pas proposé. Si SI veut que l'étape suive
   l'interrupteur, il faut fournir `tutorialsAvailable` dans `navigation`, comme
   `idKeysAvailable`.

**Texte proposé pour `docs/reference/foretmap/guide-du-prof.md`** (section des séances, hors
périmètre de F3) :

> **Étape « Tutoriel ».** Dans une séance libre, l'outil « Tutoriel » ouvre un tutoriel
> par-dessus la séance. Choisissez-le dans la liste des tutoriels actifs. L'élève le lit,
> confirme sa lecture s'il est connecté, le ferme, puis passe à l'étape suivante avec le
> bandeau ; le bouton « Tutoriel » du bandeau le rouvre. Un tutoriel désactivé ne peut pas
> être choisi, et il empêche de publier la séance tant qu'il y figure.

**Point d'incertitude pour Oliv — `tutorialId` ou `tutorialSlug` ?** Recommandation retenue
dans le code : **`tutorialId` enregistré, `tutorialSlug` accepté en entrée**.

- L'identifiant est stable : le slug d'un tutoriel est recalculé quand son titre change
  (`routes/tutorials.js`, `PUT`), une séance qui le garderait casserait au premier renommage.
- La lecture se fait par identifiant (`GET /api/tutorials/:id`), sans toucher à
  `routes/tutorials.js` ; c'est aussi la convention des autres cibles (`plantId`,
  `individualId`).
- Limite : un identifiant n'est pas le même d'une base à l'autre. Pour une étape écrite par
  migration (reprise de contenu, F1), le client sait aussi ouvrir une étape qui ne porte que
  `tutorialSlug` (recherche dans la liste des tutoriels actifs). Cette forme n'est pas
  contrôlée à l'écriture, puisqu'elle ne passe pas par l'API.
